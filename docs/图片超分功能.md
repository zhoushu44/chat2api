# 图片超分功能（腾讯云 COS 数据万象）

> 移植自 [OpenAI-Image-Super-Resolution-Proxy](https://github.com/zhoushu44/OpenAI-Image-Super-Resolution-Proxy)（Go 原生版）。
> 功能化设计：全部逻辑收在 `internal/superres` 包，主链路接线仅 3 处 × 3 行，删除功能 = 删包 + 摘接线行。

## 行为

`/v1/images/generations` 与 `/v1/images/edits` 请求的 `size` 参数：

| size | 行为 |
|---|---|
| 未填 / `auto` / `1k` / ≤1024 | 原链路，零变化 |
| `2k`（或 1025~2048） | 按 **1/2 源图尺寸**生成 → 腾讯 AI 超分 **2x** → 返回 COS 成品公网 URL |
| `4k`（或 2049~3840） | 按 **1/4 源图尺寸**生成 → 腾讯 AI 超分 **4x** → 返回 COS 成品公网 URL |

- 成品为 PNG 无损链路，不转码、不缩放（2K/4K 是超分等级，实际输出可能略超，如 4k → 6144×4096）
- **失败自动降级**：凭证错 / COS 故障 / 超时 → 日志记录 + 返回原图，服务不中断
- 环境变量 `SUPERRES_ENABLED=0` 或设置页关闭 → 完全走原链路

## 调用方注意：响应形态

超分成功时响应**固定返回 URL 形态**（`data[0].url` = COS 公网直链），即使请求里写了 `"response_format": "b64_json"`：

- 4K 成品单张 12~23MB，b64 会把响应体撑到 20MB+，不可行
- **调用方应优先读 `data[0].url` 取图**；`url` 不存在时才回落 `b64_json`（降级场景）
- URL 有效期受 COS 生命周期控制（生产配置为 7 天自动删除）；调用方需在过期前下载留存
- 判断一次请求是否走了超分：看响应 item 有 `url` 且请求 size 是 2k/4k；日志有 `[superres] done factor=...`

## 配置（二选一）

### 方式 A：控制台页面

「设置 → 图片存储与审核 → 图片超分（腾讯数据万象）」填写并保存，热生效（无需重启）。

### 方式 B：环境变量（.env / docker-compose）

```env
SUPERRES_ENABLED=1
SUPERRES_SECRET_ID=AKIDxxxxxxxxxxxx
SUPERRES_SECRET_KEY=xxxxxxxxxxxxxxxx
SUPERRES_BUCKET=your-bucket-1250000000
SUPERRES_REGION=ap-guangzhou
SUPERRES_PUBLIC_BASE_URL=https://your-bucket-1250000000.cos.ap-guangzhou.myqcloud.com
# 可选：全球加速上传端点
SUPERRES_UPLOAD_ENDPOINT=cos.accelerate.myqcloud.com
```

> 控制台保存的值优先于环境变量（settings.json 覆盖链）。

## 前置要求（腾讯云侧）

1. COS Bucket 已开通**数据万象**（图像处理）能力
2. 密钥具备：上传、删除、图片处理权限
3. 成品路径 `image-super-resolution/` 公网可读
4. **生命周期清理规则已配置**（生产 bucket `chaofengz-1318449123` 已生效：
   `superres-autoclean-7d`，前缀 `image-super-resolution/` 7 天后自动删除；
   自建 bucket 需在 COS 控制台或用 API 同样配置）

```bash
curl -X POST http://127.0.0.1:3077/v1/images/generations \

# 返回 data[0].url = https://<bucket>.cos.<region>.myqcloud.com/image-super-resolution/...
```

日志特征：`[superres] done factor=2 bytes=... url=... elapsed=...ms`

## 网关与超时（生产已核）

- 对外域名走 nginx（`token.86969678.xyz` / `img.86969678.xyz` → sub2api → 本服务），
  两处 vhost 已是 `proxy_send_timeout 600s; proxy_read_timeout 600s;`，满足 4K 最差 case（p50 180s / max 690s）
- Go 侧 COS 客户端超时 10 分钟，链路各段均 ≥600s，无短板

## 已实测（2026-10-02，真实凭证）

**链路正确性**：
- 2x：64×64 源图 → 128×128 成品 ✅（672ms）
- 4x：64×64 源图 → 256×256 成品 ✅（513ms）
- 全球加速端点上传 ✅
- 坏凭证降级：200ms 超时后原样返回原图，服务不中断 ✅

**真实尺寸基准（1024×1024 照片级复杂图）**：

| 项 | 2x | 4x |
|---|---|---|
| 超分耗时（纯腾讯环节） | 3~5s | 5~6s |
| 成品尺寸 | 2048×2048 | 4096×4096 |
| 成品大小 | ~4MB（p50 4.8MB） | ~16MB（p50 12.4MB，max 23.4MB） |
| 顺序连发 | 3 连发 2.2~2.6s，无退化 | 同左 |

**端到端参考（含生图上游，来自 89 条生产记录）**：
- 2K：p50 ≈ 119s（生图 63s + 超分链路 55s，旧架构二次上传偏慢；Go 版走上传即超分更快）
- 4K：p50 ≈ 180s
- 网关/Nginx 超时建议 ≥ 600s（Go 侧 COS 客户端超时 10 分钟）

**并发**：Go 版无应用层并发限制（对齐原代理）；生产瓶颈在生图号池，不在腾讯超分。
**成本提醒**：4K 成品单张可达 15~25MB，务必给 `image-super-resolution/` 前缀配 COS 生命周期清理规则。

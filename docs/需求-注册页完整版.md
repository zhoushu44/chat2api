# 需求：注册页完整版——三大件 + 迈巢 + warp 一次做对

> 创建：2026-09-10｜关联：`docs/需求-M3注册修复.md`（后端注册链路）、`docs/需求-注册provider配置.md`（M9 迈巢/warp 后端）
> 结论：**不打补丁、不找历史 commit**。当前源码补齐 `auto_refill` 两字段 → build → 产物整体替换 → **前端源码与产物首次全部入 git** → 验收 → 部署。

---

## 一、背景：版本为什么会漂

历史上存在三个 Register 版本，功能各有残缺，且**前端源码从未进过 git**，导致只能靠 build 产物反推版本，每次 build 结果不可复现：

| 版本 | 位置 | 特征 | 缺陷 |
|---|---|---|---|
| 旧版产物（线上跑过） | `web_dist/assets/Register-BVVJRQBa.js`（9月2日 build，57KB） | 邮箱来源框 ✓ 注册代理 ✓ **自动注册开关 ✓**（`auto_refill` + `auto_refill_interval` 30~3600s） | 无迈巢、无 warp |
| M9 新产物 | `internal/api/web_dist/assets/Register-BUl8ILnF.js`（9月9日 17:35 build，37KB） | 邮箱来源 ✓ **迈巢 ✓ warp ✓** | **丢了自动注册开关**，整体比旧版小 20KB（功能缩水，即"14509dc build 功能少"的产物） |
| 恢复版（现状） | `internal/api/web_dist/assets/Register-BVVJRQBa.js`（9月9日 18:11，57KB，=旧版原样复制） | 旧版三大件全部恢复 | 产物级恢复，**源码里 auto_refill 仍缺失**；`BUl8ILnF.js` 残留为死文件 |

**根因三条：**
1. **`web-vue/`、`web_dist/`、`internal/api/web_dist/` 从未 git add**——源码无版本控制，改丢了无法回溯（`14509dc` 在本机 git log / reflog / 全分支中均不存在，已不可考，来自上个会话对旧 Python 项目上游的叙述）。
2. **build 产物带 hash 文件名，恢复/构建时增量复制**——旧 chunk 残留（`BUl8ILnF.js` 至今躺在 embed 目录里），产物目录状态不等于某次 build 的结果。
3. **旧版 Register.vue 源码已丢失**（被 M9 改写覆盖），只剩 57KB 产物；"从旧源码重 build 复现旧版"这条路走不通。

## 二、现状盘点（2026-09-10 实测验证）

| git | `web-vue/`、两个 `web_dist/`、M9 后端（`registry.go`/`providers.go`/`provider_conn.go`）全部未提交 | 必须入库，否则继续漂 |

## 三、目标功能（验收清单）

注册页 = 旧版三大件 ∪ M9 两项，一次到位：

| # | 功能项 | 细节 |
|---|---|---|
| 1 | 邮箱来源框 | 多 provider 卡片、添加/删除/启用；provider 类型下拉含 **迈巢邮箱**（`api_base` + `api_key` 两字段，必填校验） |
| 2 | 代理框（注册代理） | 全局/直连/代理组/自定义 + **Warp 代理预设**（选中自动填 `socks5://warp-proxy:1080`，可改） |
| 3 | **自动注册开关** | `auto_refill` Checkbox（任务运行中锁定）+ **自动间隔（秒）** 数字输入，钳制 30~3600，默认 300 |
| 4 | 任务参数/邮箱请求/执行控制/实时日志 | 与现版一致，不回退 |
| 5 | 保存持久化 | 保存配置后 API 响应与重新加载均保留 `auto_refill` 两字段（后端白名单已支持） |
| 6 | 产物干净 | embed 目录内无历史死 chunk（`BUl8ILnF.js` 清除），目录=单次 build 完整输出 |
| 7 | 可复现 | `git clone` 后从 `web-vue/` build 即可得到功能等价的产物；源码与产物在同一 commit |

## 四、实施步骤

### 步骤 1：补前端类型（`web-vue/src/api/register.ts`）
`LegacyRegisterConfig` 增加：
```ts
auto_refill?: boolean
auto_refill_interval?: number
```

### 步骤 2：补 Register.vue（`web-vue/src/views/Register.vue`）
1. `defaultRegisterConfig` 增加 `auto_refill: false, auto_refill_interval: 300`（对齐旧版产物默认值）。
2. "任务参数" FormSection 的 grid 里（"检查间隔"之后）增加两个 `register-field`：
   - **自动注册**：`<Checkbox v-model="registerConfig.auto_refill" :disabled="registerConfig.enabled" />`（运行中锁定，对齐旧版 `disabled:e.config.enabled`）。
   - **自动间隔（秒）**：`<Input v-model.number="registerConfig.auto_refill_interval" type="number" min="30" max="3600" :disabled="registerConfig.enabled" />`。
3. `legacyPayload()` 增加两字段（对齐旧版产物的钳制逻辑）：
   ```ts
   auto_refill: !!registerConfig.value.auto_refill,
   auto_refill_interval: Math.min(3600, Math.max(30, Number(registerConfig.value.auto_refill_interval) || 300)),
   ```

### 步骤 3：build
```
cd web-vue && npm run build
```
产物在 `web-vue/dist/`。

### 步骤 4：产物整体替换（不是增量复制）
1. **清空** `internal/api/web_dist/`（含死文件 `Register-BUl8ILnF.js`）→ 拷入 `web-vue/dist/` 全部内容。
2. 同步整体替换根目录 `web_dist/`（保持两处一致；Go 服务实际 embed 的是 `internal/api/web_dist`）。
3. 核对 `index.html` 引用的主 chunk 与 assets 一致，无引用缺失。

### 步骤 5：本地验收（门禁不过不部署）
```
go build -o chatgpt2api-go-full.exe ./cmd/server   # 以 m9-config.json 起 :3077
```
逐项过第三节 7 项清单；重点：
- 注册页六项 UI 全渲染（含迈巢选项在类型下拉、warp 在代理下拉）；
- 开自动注册+改间隔 → 保存 → 刷新页面回读一致；
- 后端日志出现 `配置已更新 auto_refill=true interval=…`。

### 步骤 6：全部入 git（本次的核心修复）
```
git add web-vue web_dist internal/api/web_dist internal/api/providers.go \
        internal/api/provider_conn.go internal/api/auth_panel.go \
        internal/provider/registry.go docs/ .gitignore
git commit   # "M9+register full: 注册页完整版（三大件+迈巢+warp），前端源码与产物首次入库"
```
- 提交前确认无敏感文件（config/accounts/jsonl 不入库，遵循现有 .gitignore 约定）。
- push 触发 CI 构建 Docker 镜像（zhoushu1/chat2api:4.0）。

### 步骤 7：部署线上（192.6.121.16）
- 拉新镜像或上传 build 产物，替换灰度 `chatgpt2api-go-gray`（compose：`deploy/gray/docker-compose.gray.yml`），原版 :3000 不动。
- 线上过同一份验收清单；失败回滚 = 恢复备份的 web_dist（当前 BVVJRQBa 版）并重启容器。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| build 环境差异（node 版本）产出功能再次缩水 | 验收清单逐项过；源码+产物同 commit 入库，出问题可直接 diff 产物 |
| `npm run build` 报 TS 类型错 | 步骤 1 先补类型再改组件；旧版产物的字段绑定已反推确认（`e.config.auto_refill`） |
| embed 目录替换后路由/静态文件 404 | 步骤 4-3 核对 index.html 与 chunk 引用；本地 :3077 起服务全页面点一遍 |
| 线上验收失败 | 回滚备份产物；源码已入库，可本地复现排查，不再靠"找 commit" |

## 1. 目标与范围

### 1.1 目标

每日 03:00 群验时，账号 AT 失效后**不再直接禁用**，而是先尝试协议登录恢复：

```
401 群验 → 无效 ?
  ├─ 无 password/totp_secret  → 直接禁用（数据不足，无法恢复）
  └─ 有 password/totp_secret  → 协议登录（email + password + TOTP）
       ├─ 成功 → 回写新 AT/session_token → 二次验活 → 通过则保留在池，账号复活
       └─ 失败 → 禁用 + 移出池
```

### 1.2 拆段（逐项验收）

| 段 | 内容 | 可独立测试 |
|---|---|---|
| **A** | Python 导出透传 `password` / `totp_secret` / `session_token` | ✅ 可离线测 |
| **B** | Go `Account` 加字段 + admin 导入解析 | ✅ 可离线测 |
| **C** | Go 侧 RFC6238 TOTP 生成 | ✅ 可离线测（有标准向量） |
| **D** | Go 侧协议登录（signin → MFA challenge → 提交 TOTP → 拿 AT） | ⚠️ 需真实账号探索 |
| **E** | scheduler 编排：401 失败 → 尝试恢复 → 成功回写 / 失败禁用 | ✅ 可离线测（mock 恢复函数） |

**执行顺序**：A → B → C → E（用 mock 恢复函数先打通编排）→ D（最后接真实协议，替换 mock）。


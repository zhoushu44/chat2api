## 一、现场报错

Go 灰度 :3077 日志（2026-09-09 09:47）：

```
09:47:35  创建 RegiForge 任务失败：Post "http://regiforge:8787/api/tasks": dial tcp: lookup regiforge on 127.0.0.11:53: no such host
09:47:31  自动注册巡检：账号池当前 71 < 目标 100，自动补齐 29 个
```

Python 原版 :3000 同期注册正常。

## 二、根因（已查证）

| 项 | Go 灰度 :3077 | Python 原版 :3000 |
|---|---|---|
| RegiForge 地址来源 | 硬编码默认 `http://regiforge:8787`（未设 `REGIFORGE_BASE_URL`） | 同样默认 `http://regiforge:8787`，但运行环境注入了正确地址或同网络可解析 |
| Docker 网络 | 独立 bridge `deploy_gray_default`，内无 `regiforge` 容器 | 与 RegiForge 同网络，`regiforge` 主机名可解析 |
| 表现 | `127.0.0.11:53`（Docker 内置 DNS）查不到 `regiforge` → 失败 | 正常创建任务、轮询、入库 |

**结论**：不是 Go 代码逻辑 bug，是部署网络配置缺失。Go 与 Python 的注册代码对等（均 `os.Getenv("REGIFORGE_BASE_URL", "http://regiforge:8787")`），差异只在容器网络与环境变量。

### 关键代码位置（Go 版）

- `internal/register/regiforge.go:31` — `BaseURL: envOr("REGIFORGE_BASE_URL", "http://regiforge:8787")`
- `internal/register/register.go:112-114` — 同一兜底默认值
- `internal/register/register.go:697-714` — `refillLoop()` 巡检常驻 goroutine，`auto_refill=true` 时每 ≤300s 重试（持续刷红日志的来源）
- `internal/register/register.go:716-746` — `refillCheck()`：`plan = total - poolTotal`，第 743 行即报错日志
- `internal/register/register.go:141,144` — `Total` 默认 500、`TargetQuota` 默认 100；服务器上的 `100` 是面板运行时写入 `/data/register.json` 的持久化值
- `deploy/gray/docker-compose.gray.yml` — 仅设 `STORAGE_BACKEND`、`CHATGPT2API_AUTH_KEY`，**未设 `REGIFORGE_BASE_URL`**，未 join 任何 external network

## 四、修复方案（已确定：方案 B — join 外部网络 + 对齐 env）

> **探测实证（2026-09-09）**：
> - `regiforge` 容器在 `regiforge_default` 网络（ip 172.24.0.2，端口映射 `127.0.0.1:8787` 只宿主机 loopback）。
> - Python 原版 :3000（容器 `chatgpt2api`）同时连 `chatgpt2api_default` + `regiforge_default`，env 注入 `REGIFORGE_BASE_URL=http://regiforge:8787` 等 4 个值，故 `regiforge` 主机名可解析、注册通。
> - Go 灰度 :3077（容器 `chatgpt2api-go-gray`）孤立在 `gray_default`、无任何 REGIFORGE env → DNS 失败。

修复 = 给灰度容器补两点：
1. **join 外部网络 `regiforge_default`**（`regiforge` 主机名解析到 172.24.0.2，与原版同路径）
2. **注入 env 与 Python 原版逐字一致**：`REGIFORGE_BASE_URL=http://regiforge:8787`、`REGIFORGE_PROJECT_ID=chatgpt_register`、`REGIFORGE_PROXY_ID=wary`、`REGIFORGE_EMAIL_ID=mailnest`

> 已落地：仓库 `deploy/gray/docker-compose.gray.yml` 已加 `networks(regiforge_default external)` + 上述 env（见该文件注释）。服务器侧待重建生效。
> 不取方案 A（注入 IP `http://172.24.0.2:8787`）：IP 随重建漂移不稳；方案 B 与原版完全同路径最干净。原版 CAPTCHA_ID/SMS_ID 原版 env 未设，Go 也不设，保持一致。

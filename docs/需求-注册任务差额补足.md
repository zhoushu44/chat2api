# 需求：注册任务模式差额补足（三种模式 + 自动注册开关驱动）

> 创建：2026-09-14｜关联：`docs/需求-注册页完整版.md`（注册页三大件）、`docs/需求-M3注册修复.md`（后端注册链路）
> 结论：把「差额补足」的判定条件从「模式 == 按数量注册」改为「勾选了自动注册」，并让三种模式各有正确的「现有量」统计口径。

---

## 一、背景：现状问题

注册页「任务模式」有三个选项（`web-vue/src/views/Register.vue:1022-1026`）：

| 值 | 标签 |
|---|---|
| `total` | 按数量注册 |
| `quota` | 达到额度停止 |
| `available` | 达到账号数停止 |

**现状缺陷（`internal/register/register.go`）：**

1. **只有 `total` 模式做差额补足**（`Start()` 的 `switch mode`，register.go:535-559）：
   - `total`：`plan = total - poolTotal`
   - `quota`：`plan = TargetQuota`（直接用，不减）
   - `available`：`plan = TargetAvailable`（直接用，不减）
2. **`quota` / `available` 没有真正的「达标停止」**：
   - `Stats.CurrentQuota` / `Stats.CurrentAvailable` 只声明未赋值，全代码无统计逻辑
   - `AutoFollow = (mode == "total")`（register.go:609）——差额续跑被硬绑 `total`
   - `maybeContinue()`（register.go:786-822）写死 `mode != "total"` 直接 return
   - `EnsureTarget()`（register.go:922-941）同样写死 `mode != "total"`
3. **账号数统计不区分状态**：`defaultPoolFunc()`（register.go:371-389）只 `len(accounts.json)`，把限流/失效号也算进去。
4. **自动注册开关（`AutoRefill`）与差额补足无关**：它只管定时巡检拉起，不参与「算差额」。

## 二、目标语义

**核心规则：只有勾选「自动注册」（`auto_refill = true`）时才补差额；不勾选则按填的数量注册一轮，不补差额、不续跑。**

勾选后，三种模式各自补差额，跑完一轮检查是否达标，未达标继续补，算出 `<= 0` 视为已达标直接结束：

| 模式 | 目标字段 | 「现有量」统计口径 | 差额公式 |
|---|---|---|---|
| 按数量注册 `total` | `total` | 现有**所有账号**条数（不过滤状态） | `total − 所有账号数` |
| 达到正常账号数停止 `available` | `target_available` | 现有**状态为「正常」的账号**数 | `target_available − 正常账号数` |
| 达到额度停止 `quota` | `target_quota` | 现有**正常账号的额度字段之和** | `target_quota − 正常账号额度总和` |

**「现有额度」取数口径（办法1，本次采用）**：直接读 `accounts.json` 里每个状态为「正常」账号的 `quota` 字段求和，不调号池刷新接口。
- `quota < 0`（无限额度哨兵值）按 0 计入，不参与求和（避免负数拉低总和）。
- 额度可能是旧值，属已知取舍：快、无阻塞，符合「简单优先」。

## 三、改动清单

### 1. 前端改名（`web-vue/src/views/Register.vue`）
- `达到账号数停止` → `达到正常账号数停止`（registerModeOptions，Register.vue:1025）

### 2. 账号统计口径（`internal/register/register.go`）
新增三个统计方法（读 `accounts.json`，复用现有解析约定，兼容 map/数组两种格式）：
- `poolTotalCount()` —— 所有账号条数（现有 `defaultPoolFunc` 语义，保留）
- `poolNormalCount()` —— `status == "正常"` 的账号数
- `poolNormalQuota()` —— `status == "正常"` 且 `quota >= 0` 的账号 `quota` 之和

账号状态常量对齐 `internal/account`：`StatusNormal = "正常"`（不用 import account 包，避免循环依赖，用字面量并加注释）。

### 3. `Start()` 分支改造（register.go:530-561）
- 判定「是否补差额」的条件从 `mode == "total"` 改为 `s.cfg.AutoRefill`（勾选自动注册）。
- 三种模式统一：`target` 与 `plan` 按上表口径计算；`plan <= 0` 直接记日志结束。
- 不勾选 `AutoRefill` 时：`plan = target`（按填的数量注册一轮）。

### 4. 续跑/停止改造
- `startTask()`：`AutoFollow = s.cfg.AutoRefill`（register.go:609），不再绑 `mode == "total"`。
- `maybeContinue()`（register.go:786-822）：去掉 `mode != "total"` 限制，按模式选对应「现有量」统计函数判断是否达标。
- `EnsureTarget()`（register.go:922-941）：同样去掉 `mode != "total"` 限制，按模式选统计函数。
- `Stats.CurrentQuota` / `Stats.CurrentAvailable` 在轮询刷新时赋值，前端可见当前量（顺带补上这两个一直空着的字段）。

### 5. 不动的部分
- `regiforge.go` 的 `CreateTask(plan, threads)` 接口不变（RegiForge 侧只认注册数量）。
- `quota` / `available` 的「差额」在 Go 侧算好后再下发数量，RegiForge 无需感知模式。

|---|---|---|
| 1 | 不勾自动注册 + `total` | 只注册 `total` 个，不减现有 |

| 3 | 不勾自动注册 + `quota` | 只注册 `target_quota` 个 |

| 7 | 勾自动注册 + 已达标（现有量 ≥ 目标） | 直接结束，不创建任务 |
| 8 | 勾自动注册 + 一轮跑完未达标 | `maybeContinue` 继续补差额 |
| 9 | 前端模式下拉显示「达到正常账号数停止」 | 文案正确 |
